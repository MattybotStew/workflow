# 02 — Build the knowledge base

**Use in:** Phase 3, Kickoff (Design).
**Input:** `agent.md` and the client docs in `assets/`.
**Output:** files in `research/`.
**Rule:** same artifact as the manual workflow — a knowledge base that grows
with the project.

---

Read `agent.md` and every document in `assets/`. Build the knowledge base in
`research/` as separate files, one per topic. Create only the files the material
supports; skip a file and say so if there is nothing to put in it.

Suggested files:

- `brief.md` — what we are building and why, in plain language.
- `audience.md` — who it is for, what they care about, how they will use it.
- `content-inventory.md` — every piece of content, where it lives, its state
  (final, draft, missing, outdated).
- `constraints.md` — technical, brand, legal, budget, and timeline limits.
- `glossary.md` — the client's words and acronyms, with plain-language meanings.
- `open-questions.md` — anything unresolved, with an owner and why it matters.

Rules:

1. Cite the source for every claim: the file in `assets/` it came from. No
   uncited claims.
2. Do not smooth over contradictions. Record both positions and flag them.
3. Keep it factual and readable. This is a knowledge base, not a report.
4. If the same fact appears in two shapes, keep the more specific one and note
   the other.

End with a short list: what you could not determine, and what the PM needs to
confirm with the client.
